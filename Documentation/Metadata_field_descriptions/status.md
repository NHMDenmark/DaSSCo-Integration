## "status"

**Data type:**  
String  

**Value:**  
Examples: "for processing", "being processed", "working copy", "archive", "processing halted", "for deletion", "issue with media", "issue with metadata".

**Description of metadata field:**  
Status describing what the asset is currently doing. This is meant as an overall status and not to specify which part of the status the asset is currently in/doing. Fex "being processed" would not give information about the current part of the process. Values come from an enumerated list of strings. This list can be edited in the ARS with admin privileges through an endpoint.Required field for creating an asset in ARS.

**Populated by whom and when:**  
Populated by ingestion server or when an assets metadata is first created.

**Updated where and when:**  
Integration server  when an asset changes its status within the pipeline.

**Generated by:**  
Ingestion server or pipeline scripts.

**Maps to in ARS:**  
status

**Maps to in Specify:**  
None

**Notes and issues:**  
Need a new list of status. Is used for cases of derivatives not being created. Using the status issue with media. Use case for auditing being in progress. Suggested list of status: IN_PIPELINE - while automated processing is happening, ERROR - automated processing failed, DELETED - asset media was deleted, CORRUPTED - something has gone horribly wrong and asset is in an unsalvageable state, AUDITING - auditing in progress, WORKING - someone is working with this asset manually, ARCHIVED - asset has finished automatic processing and can be accessed.
